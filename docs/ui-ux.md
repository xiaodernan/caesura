## 0. 设计原则与资产策略如实声明（需求 §41/§42/§51）

**AAA premium 的落地定义（WebGL 环境下我们靠规则而非素材）：**

1. **克制**：默认屏幕元素 ≤ 3 组（HP/体力/资源），其余战斗渐显（§3）。
2. **一致**：全部界面共用一套声纹视觉语言（§1）、一套色板（art-direction.md §2 表）、一套动效缓动（统一 `cubic-bezier(0.22,1,0.36,1)` 入场 / `(0.55,0,0.1,1)` 退场；面板动画 180ms，数值补间 300ms）。
3. **响应**：任何输入 ≤ 100ms 内必须有视觉或听觉反馈；菜单导航音 ≤ 40ms 延迟。
4. **可读**：见 §7 可访问性双通道原则——**信息永远不依赖单一通道**。

**实现技术分层（如实）**：

| 层 | 技术 | 用于 | 状态 |
|---|---|---|---|
| DOM/CSS 层 | HTML overlay（backdrop-filter、CSS transform） | 全屏菜单/背包/地图/设置/对白 | 主实现 |
| Canvas 2D 层 | 独立 `<canvas>` 叠于 WebGL 之上 | HUD 仪表（数值绘制锐利、重排 0 成本） | 主实现 |
| WebGL scissor 层 | three.js 局部视口 | 角色/装备 3D 预览、世界空间名牌投影 | 主实现 |
| 字体 | 系统字体栈 + 程序生成声纹装饰字形（无商业字体采购） | 全部文本 | Placeholder→可换自研字形 |

- 基准设计分辨率 1920×1080；安全边距 5%；HUD 元素按 `min(vw/1920, vh/1080)` 等比缩放，4K/超宽屏只扩留白不拉伸。
- 无外部 UI 素材库：面板/图标全部 Canvas/SVG 程序绘制（振膜纹理=程序干涉条纹）。

## 1. 声纹视觉语言组件库（每组件：布局 + 状态）

### 1.1 振膜面板（Membrane Panel）——一切面板的容器

- **布局**：任意矩形容器；边框 1px `#E8DFCB` 30% 透明；底 = 深色区板 BASE @ 82% + `backdrop-filter: blur(8px)`；表面叠极淡同心声纹（CSS radial repeating-gradient，透明度 ≤ 4%）。
- **状态**：`idle` 静止 / `hover` 光标进入→同心波纹从最近边缘向光标**扩散一次**（300ms，点击感=膜的振动）/ `open` 从内容中心"张膜"缩放 0.96→1 + 透明度 / `close` 反向 150ms / `alert`（获得稀有物）表面干涉条纹亮一拍。
- 规则：波纹永远从"声源点"发起——与 art-direction.md §1.1 同一物理，UI 是世界的延伸。

### 1.2 声纹字体装饰

- 标题字间距 +8%，标题下沿常驻一条 12% 透明度的波形线（该标题文本的**真实声纹**：默认词表名按音节程序生成波形，固定 seed——同一标题永远同一条纹）。
- 正文禁止装饰；数字使用等宽 tabular-nums。Boss 名/区域名首次出现播放"显名"动画：波形线从左侧画入 → 名字逐字浮现（16ms/字）。

### 1.3 HP 振幅条（Amplitude Bar）

- **布局**：左下，水平 320×26px。外形不是矩形条——是一条**波形**：波峰高度 = 当前 HP 比例，波形基频恒定，受损时高频碎裂感增强。
- **状态**：`full`（>80%）平稳波 / `hurt` 受击：波被"打断"一个缺口，240ms 愈合；缺口起点=伤害来源方向（左侧受击缺口在左）/ `low`（<30%）波形变锯齿 + 色从 `#FFB86B` 渐染 `#A8322E` + 0.8Hz 微脉动（配心跳音，audio.md §5）/ `dead` 波形拉平为直线（心电停止意象）。
- 治疗：波形从右侧"重新填满振动"，不用绿色（本作无绿血药惯例，音色石橙治疗光）。

### 1.4 体力节拍环（Beat Ring）

- **布局**：HP 波右侧，直径 56px 圆环，中心为空（露出游戏画面）。
- **表现**：环以**当前战斗 BPM**（BeatClock，audio.md §2）做呼吸缩放 100%→104%——体力可视化即节奏可视化。消耗：环按扇形顺时针"剪缺"；回复：缺口随下一个节拍点补回一格（离散拍点回充，非连续——玩家用耳朵学回充节奏）。
- **状态**：`ok` 骨白 / `heavy-cost` 重击后瞬时琥珀 / `exhausted`（0）环整体变灰红、停止脉动并**碎裂纹样** 400ms—— exhaustion 必须"看起来哑掉了"（世界观：你的节拍断了）。

### 1.5 共振过载条（休止资源条，需求 §42 Resource）

- **布局**：体力环下方，120×8px 细条；音叉图标端点。
- 弹反/完美格挡积累（每层 +34%），满条时音叉两齿发光 + 环境音轻微下沉预示（可触发"休止处决"）。

### 1.6 Boss 乐句进度线（Phrase Line）

- **布局**：屏幕底部居中，宽 55% 屏幅。一根横线=一条"乐句"（Boss 血量），线上小节刻度线 = 阶段分界（60%/25%），右端刻 Boss 名（声纹字体）。
- **状态**：`intro` 线从左画入 + 名字显名动画 / `combat` 伤害以"擦除音符"方式从右向左消耗，重击一次擦过多小节刻度时线身闪干涉纹 / `phase` 越过刻度：线短暂"走调"（波动扭曲 600ms）再重新拉直 / `stagger`（振源核破）线整体变金并出现第 5 拍的额外刻度=处决窗口邀请。
- 恩希尔特殊：P1 小节刻度**随机漂移不固定**（无拍长），P2 玩家夺拍时刻度逐个钉回——UI 也在演叙事。

## 2. HUD 信息层级与出现规则（默认极简，需求 §42）

层级：P0 常驻 / P1 战斗渐显 / P2 事件闪现 / P3 菜单专属。

| 元素 | 层 | 出现条件 | 隐藏条件 |

| 交互提示（E） | P2 | **已实现（Phase 3-C1/C3）**：底部居中 `[E] 动词 · 区域名` 一行（金色 `[E]` + 骨白文案 + 细金基线），由 `world/Interactables` 在焦点变化时推 `ui.prompt`（载荷带 `id`，占位模据此点亮）；当前焦点半径 6m（3D 距离），单焦点优先（最近者），动词取数据 `verb` 或 kind 默认 | 移出即淡出（`promptA` 指数衰减 ~90ms 时间常数）；死亡时强制隐藏。交互物已有占位模（`InteractableGreybox`，KI-013 降为 Partial），种类图标与 3m 收紧仍待正式模（Phase 7） |

| 拾取通知 | P2 | 右侧滑入振膜小卡，堆叠 ≤3 条 | 4s 自动收起 |
| 伤害数字 | — | **默认关闭**（AAA 克制）；设置可开（仅出伤/仅承伤/全部） | — |
| 罗盘/任务方向 | P2 | 只有一条淡金色声纹线贴屏幕底部指向（不做箭头堆） | 进战斗自动隐藏 |

## 3. 全屏清单（逐屏线框描述）

通用骨架：全屏菜单 = 背景（游戏画面高斯模糊 + 压暗 55%）+ 振膜面板层。左缘竖排标签导航（图标+字，48px 宽栏），内容区右侧展开。任何菜单 B 键/Esc 直接返回游戏（暂停但世界不冻结存档检查）。

### 3.1 主菜单（Title）

```
[全屏：凝声极光带实时 shader 场景，休止背影剪影立于哑带边缘]
  居中偏左：LOGO「CAESURA 止音纪元」+ 标题下声纹线画入
  纵列：继续冒险 / 新游戏 / 设置 / 退出     （24px 字高，hover=膜波纹扩散）
  右下：版本号 + 存档摘要卡（角色名/区域/时长）
  "新游戏"若已有存档 → 振膜确认子面板（防误删，需求 §45  corruption prevention 的 UI 端）
```

**名册问不出来的时候要说，也要留一条路（KI-386，2026-11-03）**：上面那块线框里「继续冒险」与「新游戏 → 振膜确认子面板」这两条都建在「问得到本机有几格档」之上。那一问今天只写了成功那一路，所以一次读失败会把整屏停在「正在查看本机存档…」——既开不了新局也看不到坏在哪。现在的约定是：① **失败要说自己的原因**（页脚那句改成「本机存档问不出来 · 原因原话」，挑档屏那一片说同一句话，而不是空一格）；② **坏消息不许成死路**（这一格照样按 ↓ 进得去挑档屏）；③ **不知道就不赌**（名册还在路上时点卡仍不动，这是 KI-025② 的裁决），但问不出来时点卡落在确认屏，措辞从「本机已有可读的存档」换成「可能覆盖一份看不见的存档」——两种「要先问一句」不许共用一句假账，默认项仍是「取消」。文案住在 `src/ui/TitleScreen.ts`，屏上不出现第二份说法。

### 3.3 装备对比 Current vs New（需求 §44 硬要求）

- 悬停/选中未装备物品时，详情区自动分左右双栏：

```
┌ CURRENT（左，40% 透明标题） │ NEW（右） ┐
│ 图标  调律剑·无名音叉        图标  弦棘断刃 │
│ 攻击力   112   →  ▲ +18  (130)              │  ← 差值行：升=琥珀▲ / 降=暗红▼ / 平=灰—
│ 重量     8.4   →  ▼ -1.2 (7.2)              │
│ 暴击率   5%    →  ▲ +2%                     │
│ 特殊：音叉共鸣  vs  特殊：震裂+1 层          │
│ [装备 E]        [对比锁定 Tab 常驻显示]      │
└──────────────────────────────────────────┘
```

- 规则：**每行差值必须可见**（不允许只显新物品属性）；综合"更适合当前 Build"的一栏由权重算法给出建议星标，但玩家可否决（不做数值保姆）。切换装备即时：面板不关，角色 3D 预览 250ms 换装动画。
- **实装状态（2026-09-24，KI-027）**：双栏对比**已落地**，按本节字面实现——候选件行下方挂一块 `当前 / 差值 / 换上`，`▲ 琥珀 / ▼ 暗红 / — 灰`三种形状（不靠颜色单独承载），每一行都带差值（「—」后面也写 0，只画一个破折号等于要玩家自己心算）。两栏都是**整套**乘数（不是这一件的属性），因为词缀、强化倍率、音徽 A/B、噪音的加总偏移都在 `Equipment.totals` 里；"New"那一栏走 `Equipment.preview`（把这件装到它自己的槽位后重算，投影不碰真实槽位）。**三件事按字面实现会出事，都登记着**：①"更适合当前 Build"的星标建议**没做**——那需要一张维度权重表，权重是数值不是排版，抄进代码就是第二类答案，而它的表落点要动正被并行会话写的 `schema.ts`（KI-027）；**① 已落（KI-060，2026-09-26）**：表在 `progression.json > gearAdvice.weights`（14 条数值轴，每条一个"建议分/单位增量"，负重与噪音是负数），评分走 `Equipment.adviceDelta` = 拿 `preview` 的整套投影减掉现在这一身，所以词缀、强化倍率、音徽 A/B 与乘数轴的基线都在差里自己抵消；每格只标分数最高的一件，而且**分数 ≤ 0 的一律不标**（换上更差的东西不配叫建议）。本节那句"玩家可否决"是这条逻辑的硬边界：★ 不参与许可判断，装哪一件永远许可（`tests/unit/gear-advice.test.ts` 有一条专门钉它）；②「升=琥珀/降=暗红」在**负重与噪音**两行是反的（这两行越低越好），本环境看不到颜色对照，先按字面实现，等一次视口/手感走查裁决；③「即时换装 + 3D 预览 250ms 动画」没有 3D 预览视口（KI-010 同因），面板只做数值槽位、换装本身是即时的。

## 4. 地图系统（需求 §43）

### 4.1 结构

- 两级：`区域图`（息声领全图，7 区色块）与`详图`（单区，含垂直分层——每区最多 4 层剖面，层间以 tab 切换：地表/崖壁/地下/深层）。
- 详图渲染：预烘 SVG 底图（程序生成）+ Canvas 标记层；垂直层用叠层透明度表达（上层 35% 透明）。

### 4.2 渐次揭示（Discovery Reveal）

| 状态 | 表现 |
|---|---|
| 未知 | 磨砂遮罩 + 声纹噪点（"听不见的地方"） |
| 远望已知 | 进入视野轮廓：仅露剪影线条，无细节（从某高点望见钟坠院→轮廓解锁） |
| 踏足 | 0–160m 半径内细节渐显（600ms 水波式淡入，进入即"录下这段声纹"） |
| 调音桩激活 | 该桩成为快旅点 + 周围 240m 全显 + 解锁其"音壁后"隐藏连通 |

- 不显示：未踏足区的敌人、可拾物。任务标记只给**方向区段**（"雾语林东部"），不给坐标钉——探索权在玩家。

### 4.3 操作与标记类型

- 缩放：0.5×–4.0×（12 级离散+平滑滚轮），缩略图模式 <0.7×（隐藏路径只显区色块）；平移：拖拽/摇杆（惯性 0.15）、`F` 一键回中到玩家；快旅：详图上选中已激活调音桩 → 确认振膜面板。
- 标记类型表（图标共用声纹语言，颜色取 art-direction §7.1 语义轴）：

| 标记 | 图形 | 来源 |
|---|---|---|
| 玩家 | 音叉指针（指向镜头朝向） | 常驻 |
| 调音桩 | 小石针+微光 | 自动 |
| 地标 | 双刻度括号包围的剪影符号 | 远望即显 |
| 商人/NPC | 琥珀圆点+首字声纹 | 遇见后 |
| Boss/Mini Boss | 钟形/王冠形金符号 | 情报获得后（非自动！） |
| 玩家手钉 | 自定义 16 个，长按钉制，hover 显示自定文字 | 手动 |
| 捷径（打开的门/电梯） | 细线连通动画 | 通过后 |

`pick1..9`（面板不必知道接的是哪一块键盘，两块同时按也只发一次）。于是 `UiIntent` 的完整值域是 `up/down/left/right/confirm/back/pagePrev/pageNext` + `pick1..9`。**两个后果值得写在这里**：① 地图上多了一条真活腿——`MapUI.uiStep` 在方向都抵消时那个提前 `return`，批30 判它恒死时名册只有八格且全被上面吃净，数字意图进来之后它有了读者，读出来的效果就是"静默"（地图没有编号行，不许按 3 跳到第 3 个设施）；② 标题屏是**根**，根屏的 `back` 一格效果都没有（不是漏接），而 `dispose()` 现在先灭 `on` 再摘 DOM，所以退场之后就算还有意图喂进来也不重画。**标题阶段 `GameLoop` 还不开**（`time.tick` 停在 0 是 KI-031② 的实测读数），那一屏的读数由 `core/Input.ts` 的 `pumpMenu(input, feedMenu)` 提供：一帧一次 `poll` + 一次喂读，dt 钳与 `GameLoop` 同一把（0.25s），决策一出口就 `stop()`。仍欠的仍是 §6 那格"全键位重映射"的**玩家入口**那一半：`UI_BINDS` 不再是常量表了（KI-336，2026-10-28）——两张默认表成了 `Input` 手里的**运行时数据**（`setBindings()` 一次换整张并清空 held，`binds`/`uiBinds` 两个 getter 是给 HUD 与面板的读数，所以"改键之后面板不会说谎"这句话第一次由用例量出来），名册收成值（`BINDABLE_ACTIONS`/`UI_INTENTS`，`ActionName`/`UiIntent` 从值现推），`settings/Bindings.ts` 的 `clampBindings` 是读档路径上唯一被信任的入口。两条通道各自有各自的**折叠规则**，这不是偶然：玩法那条一个动作一把键（HUD 那一列与槽位标签显示的就是"一把键"），菜单这条**不折叠**——上面那句"键盘不给 `Space`/`E` 才是设备间的不一致"是设计，`confirm` 的四把等价键一份档没点名时整组回归、点了名才整组换掉。手柄那条同理：默认表本来就一键多用（0 与 12 `clampBindings`），回补那一遍**两遍**都跳过点了名的值，所以"玩家说不要"不再是一句建议；界面上那一格住在 §5.1 的「操作」页（每行第三格「解绑」）。当时仍欠的是**菜单那条**的改键与「无」，以及**手柄那侧的「无」**（玩法键盘与手柄那两张今天都能逐行改，KI-343，2026-10-29；一屏两列、两条通道各一把「改键」与一把「回默认」）——前一样已在 KI-344 落地（见本节末与 §5.1），登记同上。**动手改键的那个界面已落（KI-337，2026-10-28）**：面板第七页「操作」逐行可改，捕获住在 `core/Input.ts`（面板自己挂 `keydown` 会被上面那条源码闸门当场判红，所以"下一枚物理键"这件事只能问已经有那一条监听器的人），等键途中两条通道都哑、`Escape` 算取消。本节"禁用行可以被选中但不可以被执行"那条口径在这一页第一次被**数值端点**用到（◀ 到底写成 `disabled`，键盘/手柄那条自己挡），而这一屏的每一格都只用 ↑↓/Enter 走得到——包括点「改键」那一步。**菜单那条通道的逐行改键与「无」也已落（KI-344，2026-10-29）**：同一屏多出第三节 17 行（`UI_INTENTS` 每行一格「改键」），而这一节的**单元是整组**——`confirm` 那一行画的是它此刻握着的全部等价键（默认表上是 `Enter、NumpadEnter、Space、E` 四把）而不是第一把，改这一行＝只留按下的那一把，被顶掉的那个意图按同一套整组语义走（还剩别的键是「少了一把」，一把不剩是「整组搬了家」）。这一节的「无」同样要两半（表里没它＋名单里有它，名单住在 `UiBinds.unbound`，唯一书写者仍是 `clampBindings`），而**名单里有一格永远进不来**：`back` 不许关，因为「菜单必须走得出去」——关掉 `confirm` 只是少一种能力，关掉 `back` 是把这一屏变成陷阱；这句话只有一个主人（`UI_EXIT_INTENTS`）与三个读者（写的那侧返回假、读的那侧从档里丢掉、画的那侧不出现「解绑」而是写明为什么）。这一节的等键那一步也只用方向键与 Enter 走得到，而那句页脚要**带节名**（`等待一枚键 · 菜单导航 · 后退`）：玩法与菜单各有一格叫「后退」，光靠行名分不开。仍走不通的那一格——**手柄那一侧的「无」**——已由 KI-346 接上（菜单那一节的手柄列与 `ui.stickThreshold` 的入口更早，KI-345：那一节也是两列、两把「改键」两把「回默认」，阈值那一格到界写 `disabled`，等键那一步也只用 ↑↓/Enter 走得到）：那一列上从此多一把「手柄解绑」与一把「手柄回默认」，而"两种来历分不开"的根因是名单只有一份——现在每表一份（`gameplay.padUnbound`／`ui.padUnbound`），「—」＝没人认领、「无」＝玩家说过不要，登记同上。

## 7. UX 评审清单（需求 §81，每个界面 ship 前逐条过）

- [ ] **可理解**：不看教程，新玩家 10s 内能说出这屏是干什么的？（盲测 3 人）
- [ ] **可发现**：核心操作（弹反/休止/快旅）在暂停菜单里能否 2 步内查到输入提示？
- [ ] **可操作**：全路径手柄可达？任何按钮目标命中区 ≥ 44×44px（1080p）？
- [ ] **有反馈**：每次输入 ≤100ms 反馈？每次成功/失败有区分音（R-1 上行 vs 倒影）？
- [ ] **无摩擦**：装备物品 ≤2 键（选中→E）；买/卖 ≤3 键；地图找到快旅点 ≤3 步；对比信息无翻页（差值一屏内）。
- [ ] **极简守恒**：战斗 HUD 常驻元素 ≤4；截图检查"屏幕堆数字"即驳回。
- [ ] **一致**：色/字体/动效缓动/圆角（全 4px）来自本文件与 art-direction §2，无孤例。
- [ ] **可访问**：双通道检验——静音可玩（视觉全达）+ 盲音测试（关键信息是否都有声音冗余）；色彩降级下信息不丢失。

## 8. 存档/读档 UX（需求 §45 的界面侧）

- 自动存档：调音桩休息、区域切换、Boss 战后；UI 表现=音叉图标涟漪一次（不打断）。
- 损坏防护：双写（slot.a/slot.b）+ CRC 校验，读档失败自动尝试备份并在槽卡上显示"已恢复备份"黄标；版本迁移失败 → 明示"该存档版本过旧"而非静默清空。
- 死亡→重选界面：休止主题——"你的节拍停在这里"，一键回到最近调音桩，显示魂值（货币）掉落点标记（死亡地=可回收声钉）。

**实装状态（KI-025①②，2026-09-26）**：本节除"音叉图标涟漪"（图标位仍是文字，见 KI-027）与死亡→重选那一屏之外都已落地，形状与本文略有出入的是**位置口径**而非取舍：

- **能做什么由站在哪儿决定**——读档只在标题屏（`ui/TitleScreen.ts` 的选档页，那里没有写入/删除按钮），写入与删除只在调音桩面板第六页（`ui/Stakerite.ts`，那里没有 `load` 这个动作）。"继续冒险"因此是标题屏的一行，不是面板里的一个按钮。
- 摘要卡的候选口径是**四格名册**（自动槽常驻第一格 + 槽 I/II/III），卡面六格＝音级 / 出身·武器 / 区域 / 游玩时长 / 存档时刻 / 来源；出身与武器的中文名从装备表反查（表里没有中文名就不显示，不拿 id 冒充）。缺的格**留空**：v1 老档显示"音级 未知 · 出身 未知"，v9 老档显示"时间未记录"。截图位没有（面板与标题屏共用 `ui/SaveSlots.ts` 那一套 em 尺寸的卡）。
- 损坏防护的实现是 **tmp/prev/备份三级回退 + CRC**（`save/Serializer.ts` 的 `slotCandidates`/`readSlot` 是全仓库唯一的读档顺序，名册与 `load()` 共用它，所以卡上写"可读取"就一定读得出同一格）；"已恢复备份"黄标带来源键位（`slot1.prev` 与 `slot1@backup` 分得开）。四种坏因各自一句原话：JSON 读不懂 / 不是本游戏的档 / 版本读不了（缺升级步骤时明示，不静默清空）/ CRC 不符。
- 防误删确认是**两步**：面板里"写入/删除"的第一下只把那一笔记成待确认并写明后果（空槽/覆盖谁/含备份位），第二下才落盘；标题屏"开一根新弦"在机器上有可读档时进确认屏，且默认焦点在"取消"。只有坏档没有可读档时，标题屏给的是"查看"入口而不是"本机没有可续的存档"。
- 守卫：`tests/unit/slots.test.ts`（名册与 IDB 形状）、`save-ui.test.ts`（真档读回的卡面不许有编出来的字）、`title-screen.test.ts`、`stakerite.test.ts` 存档页 10 条。仍缺：手柄导航、排版/热区手感走查（KI-010/027 同因）。
