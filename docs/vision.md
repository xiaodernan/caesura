## 0. 一句话定位（One-liner）

> **CAESURA《止音纪元》**是一款原创 IP 的第三人称动作 RPG：世界是一首唱到一半被斩断的歌，
> 你是唯一听不到残响的聋者「休止」——在一个用**节拍**思考的战斗与探索体系里，让失控的世界**安静下来**。

| 维度 | 定位 |
|---|---|
| 品类 | Third-Person Action RPG（第三人称动作 RPG），单机 |
| 世界形态 | 半开放区域 Vertical Slice：息声领（Restreach）单区高完成度，后续扩展 |
| 核心幻想 | **减法型超能力**：不是"更响"，而是能让一切振动"停下"（弹反/处决/净化的世界观依据） |
| 差异化 | 战斗与世界共享**真实节拍网格**；聋者视角的"可视化声纹"表现语言 |
| 平台/技术栈 | 浏览器 3D：Vite + TypeScript + Three.js（WebGL2） |
| IP 状态 | 完全原创（世界观/角色/Boss/武器/音乐/视觉语言，需求 §86） |

## 1. 产品定位（Product Positioning）

### 1.1 体验目标：AAA 品质标准，而非 AAA 具体内容

参考对象是**品质标杆（quality bar）与设计原则**，不引用、不复刻任何已有商业游戏的具体内容
（需求 §5/§85/§86；IP_SEED §16 红线）。我们学习的是这些层面的原则：

| 借鉴的设计原则 | 在 CAESURA 中的原创表达 |
|---|---|
| 战斗难度来自模式识别与学习，而非血量海绵（需求 §23） | Boss 攻击全部落在可听、可见的节拍网格上；「夺拍」机制把"学习"本身做成玩法 |
| 区域密度优先于面积，"那边是什么"的持续牵引（需求 §7） | 息声领六区块每块强制含 Landmark / Secret / 遭遇 / 环境叙事 / 捷径 |
| 垂直结构串联多层地图（需求 §10） | 休垒→雾语林（地表）→钟坠院（崖壁）→沉唱堂/无耳深窖（地下）→初句圣所（隐藏） |
| 环境叙事：世界自己讲述（需求 §29） | 破拍营地士兵保持着生前军阵巡逻；凝声极光带黯淡=看得见的末日倒计时 |
| 丰富但不臃肿的 RPG 系统（需求 §25） | 升级必须产生可感知的玩法变化，拒绝无意义数字膨胀 |

### 1.2 技术基线与诚实的限制记录（需求 §3 第 1-4 条）

**事实记录**：需求 §3 的技术基线为 Unreal Engine 5.x（Nanite / Lumen / World Partition / Niagara 等）。
当前环境**无法使用 UE5**：本机无引擎安装、无 C++ 编译工具链、磁盘空间不足。
按需求 §3 的处理原则，我们**不伪装已实现**，采用替代方案并保留升级路径：

| 决策 | 内容 |
|---|---|
| 当前栈 | Vite + TypeScript + Three.js，浏览器内原生 60 FPS 目标的第三人称 ARPG |
| 替代原则 | UE5 每项能力映射到 Three.js/WebGL2 可达的近似方案，逐项登记于 `docs/production-plan.md` §1 |
| 保留升级路径 | 架构层强制数据驱动（JSON/TS 配置表）+ 模块化系统边界 + 资产接口标准化（glTF/skeleton 约定），使战斗数值、AI 行为树、关卡布局、资产清单可整体迁移至 UE5 |
| 如实声明 | 系统状态词表 Implemented / Partial / Placeholder / Blocked（需求 §78）贯穿全部文档与 KNOWN_ISSUES.md |

### 1.3 交付形态

| 阶段 | 交付物 |
|---|---|
| M-A（当前） | Phase 0 文档集（本文 + `docs/production-plan.md` 等） |
| M-B | Core Combat Prototype：浏览器内战斗原型可玩（Phase 1-2） |
| M-C | Vertical Slice：30–60 分钟高完成度闭环（IP_SEED §15；需求 §60/§73） |
| M-D | 完整产品扩展路线：多区域、更多 Boss、内容管线复用（远期；UE5 迁移作为可选项保留） |

### 1.4 市场与存在理由（Why this, why now）

| 问题 | 回答 |
|---|---|
| 为什么是浏览器 3D？ | 零安装即点即玩是同类重度 ARPG 体验从未有过的分发形态；"30 秒进入 Boss 战"本身即卖点。限制如实记录于 §1.2 |
| 为什么原创 IP 而不是授权/模仿？ | 需求 §5/§85/§86 合规红线；且"节拍战斗+聋者幻想"作为设定-机制一体化设计，只有原创 IP 能自洽承载 |
| 为什么 Vertical Slice 优先？ | 需求 §60/§61：单区极高完成度 > 十区半成品；一个能打动人的 45 分钟闭环是全部后续投资决策的前提 |
| 与"AI 拼装 Demo"的区别？ | 每条支柱有可执行判据（§5）、每个系统有诚实状态标注（词表制）、验证以浏览器实机试玩为准——不是截图工程 |

### 1.5 命名与合规基线

| 项 | 约定 |
|---|---|
| 游戏名 | CAESURA（英文）/ 止音纪元（中文）；Caesura=诗行中的"休止"，本义"切割" |
| 词表 | 唯一合法词表 = IP_SEED §14；新增名词必须先登记再使用（文档/代码/资产命名同规则） |
| 世界观原创声明 | "以音乐比喻创世"为公有神话母题，本项目全部**具体表达**（历史/文明/地理/宗教/力量体系/神话）原创（IP_SEED 卷首声明） |
| 符号红线 | 视觉中禁止出现任何现实文化宗教符号（IP_SEED §10）；统一母题为"凝固的声波" |

## 2. 设计支柱（Design Pillars）

> 全部提炼自 IP_SEED，共 5 条。每次评审（需求 §80-§82）逐条对照；任何功能至少服务一条支柱，否则砍掉。

### P1 「战斗即音乐」Combat is Music（节拍可读性）

| 项 | 内容 |
|---|---|
| 定义 | 世界是歌声凝结，敌我攻击都发生在真实节拍网格上（IP_SEED §11）。玩家最终不是"反应快"，而是**会读谱**：鼓点、钟声、乐句就是敌人的前摇语言 |
| 玩家获得 | 从"被动画面"到"预判重拍弹反"的掌握感；Boss 战=学会一首新曲 |
| 落地锚点 | 弹反窗口对齐重拍（奥斯塔拉 3/4 拍）；恩希尔「夺拍」机制；Boss 乐句进度线血条；节拍环体力 UI |
| 裁决问题 | "这个攻击的时机，玩家不看帧数据能否只听/只看就预判？" |
| 反面 | 无节奏逻辑的随机出招；靠贴图亮度当唯一 telegraph |

### P2 「休止是超能力」Silence is the Superpower（减法幻想）

| 项 | 内容 |
|---|---|
| 定义 | 主角的权力不是输出更大伤害，而是**让振动停下来**：弹反=切断敌拍，休止处决=让失控的残响彻底安静，潜行=不被仪典"听见"（IP_SEED §2） |
| 玩家获得 | 独一无二的身份幻想：聋者反而是唯一能拯救/终结这个世界的人 |
| 落地锚点 | 共振过载（Overdrive）资源条→休止处决；隐藏 Boss 万籁的"声音狩猎"完全安静战斗；「无鸣」无声刺剑；弹反震开音壁暗门（探索用同一动词） |
| 裁决问题 | "这个系统是在奖励'停下来'，还是只会堆伤害数字？" |
| 反面 | 处决只是大爆炸演出（违反需求 §16 克制原则）；安静/噪音没有任何机制差异 |

### P3 「密不透风」Dense > Huge（一个区域的纵深）

| 项 | 内容 |
|---|---|
| 定义 | 第一阶段只做息声领，但做到每一屏都有牵引：Landmark 可达、秘密无入口可见、垂直三层、捷径回环（需求 §7-§10；IP_SEED §3/§9） |
| 玩家获得 | 持续产生"那边是什么"；抄近路回 hub 时的"这张图我懂了"的立体掌控感 |
| 落地锚点 | 六区块+初句圣所；共鸣井电梯/吊桥/可破坏音壁；地图 UI 逐步揭示（需求 §43） |
| 裁决问题 | "删掉这个空间，玩家会少一次好奇吗？"——不少就删 |
| 反面 | 为凑面积的空旷地形；十个区域全部半成品（需求 §61） |

### P4 「克制而可读」Readable, Restrained Feedback（反馈纪律）

| 项 | 内容 |
|---|---|
| 定义 | 每一次输入走完 Input→动画→音效→VFX→镜头→顿帧→振动的完整链（需求 §47），但强度分级、绝不满屏爆炸（需求 §16/§35）；VFX 首先服务可读性 |
| 玩家获得 | 按键瞬间感到重量；乱战中永远分得清"哪个攻击要打到我" |
| 落地锚点 | 聋者"可视化声纹"作为专属 telegraph 语言（金尘/地面波纹/低频震动 UI）；敌人剪影一律带可见振源核发光点；顿帧/抖镜分轻中重三档 |
| 裁决问题 | 截图单帧审查：能否 0.5 秒内找到"现在该看哪里"？ |
| 反面 | AI asset soup（需求 §82）；把所有攻击做成巨大爆炸 |

### P5 「世界自己讲述」The World Speaks for Itself（环境叙事 + 可见的倒计时）

| 项 | 内容 |
|---|---|
| 定义 | 故事主要靠建筑、尸体摆位、item 文案、敌人布置、光照与声景讲述（需求 §29）；天空凝声极光带是**世界观时钟**，随主线逐段黯淡——世界末日是玩家看得见的进度条（IP_SEED §10） |
| 玩家获得 | 自己推理出的真相比过场更可信；每次回休垒都能"看到剧情发生过的痕迹" |
| 落地锚点 | 五大 NPC 状态=任务状态+玩家选择+世界状态（需求 §30）；终局抉择改变 Hub 极光/音乐/NPC 台词；铃姨修钟→区域天气与敌人浓度变化 |
| 裁决问题 | "这段信息如果拿掉过场动画，世界本身还讲得清楚吗？" |
| 反面 | Cutscene 依赖症；打完最终 Boss 世界毫无变化 |

### 2.6 支柱冲突裁决顺序

多人格评审出现支柱间冲突时，按以下优先级裁决（越靠前越不可让渡）：

| 顺位 | 支柱 | 理由 |
|---|---|---|
| 1 | P4 可读克制 | 手感是品类入场券，不可读则一切归零 |
| 2 | P1 战斗即音乐 | 差异化本体；与 P2 共同构成"设定=机制"骨架 |
| 3 | P3 密度 | 决定 Slice 口碑上限，但可用砍面积保质量 |
| 4 | P2 休止超能力 | 与 P1 共生；单独取舍时向 P1 的普适手感让位 |
| 5 | P5 世界自述 | 沉浸放大器；允许 Placeholder 文案先行（排期见 production-plan） |

### 2.7 体验时刻（Experience Moments：每支柱一个必须复现的名场面）

| 支柱 | 名场面（Vertical Slice 内必须成立） |
|---|---|
| P1 | 奥斯塔拉的巨钟按 3/4 拍鸣响，玩家在第 3 拍重音弹反，钟声戛然而止 |
| P2 | 弹反冲击波震开"音壁"暗门——战斗动词第一次变成探索动词 |
| P3 | 钟坠院崖壁抬头：九座坠落巨钟的剪影同时构成地标、谜题与垂直路径 |
| P4 | 休止处决触发瞬间：全频段低通，世界安静，只剩心跳与骨传导低音 |
| P5 | 击败恩希尔回到休垒：凝声极光带重启一段，Hub 音乐层变化，NPC 台词全换 |

## 3. 核心体验循环（Core Gameplay Loop）

需求 §2 的循环在本 IP 中的具体化（三层嵌套，必须逐层成立）：

| 层级 | 周期 | 循环 | CAESURA 具体化 |
|---|---|---|---|
| 微循环 | 5–15 秒 | 输入→反馈 | 移动/轻攻/重攻/闪避/格挡/弹反 → 顿帧+声纹 VFX+SFX+节拍环消耗 → 敌我状态变化 |
| 中循环 | 3–8 分钟 | 遭遇→学习→征服 | 遭遇喧堕者 → 读其"曲式"（telegraph）→ 弹反积累 Overdrive → 休止处决 → 拾取音色石 |
| 宏循环 | 30–60 分钟 | 探索→成长→解锁→揭示 | Explore→Discover→Fight→Loot→Upgrade→Experiment→Progress→Unlock→Explore（需求 §2）：新区域/新 NPC/新故事 → Boss → 乐章战技（Movements）→ 回头解锁捷径 → 世界状态改变 |

循环成立的可验证判据见 §5 成功判据表；任何一层断裂即视为 P1 级核心问题（production-plan §2）。

## 4. 目标玩家（Target Audience）

| 画像 | 描述 | 对应支柱 | 关键诉求 | 我们的回答 |
|---|---|---|---|---|
| 「硬核动作 RPG 玩家」 | 精通弹反/读招/Build 规划，习惯高完成度近战与 Boss 战 | P1/P4 | 战斗要有学习深度，不要 HP 海绵 | 节拍网格战斗+振源核弱点+三 Boss 独立机制 |
| 「探索型世界旅客」 | 偏爱环境叙事、碎片化 lore、地图回环设计 | P3/P5 | 世界要密、要可信、要奖励好奇心 | 每区块强制六要素；item lore 承载正文 |
| 「氛围驱动的沉浸玩家」 | 重视美术统一性、音乐、世界观独特性 | P2/P5 | 独特视觉语言与"设定即玩法" | 凝固声波母题+区域色板+极光时钟+休止机制 |
| 「浏览器即玩人群」 | 不愿下载/等安装，用中端 PC，尝试门槛敏感 | 全部 | 打开链接 30 秒内开始玩 | Vite 秒开 dev、无安装、60 FPS 目标+画质四档 |

非目标玩家（明确不服务）：多人协作玩家（单机）、放置/数值抽卡玩家、只玩触屏的玩家（键鼠/手柄优先，触屏非验收范围）。

## 5. Vertical Slice 成功判据（Success Criteria）

> 闭环内容 = IP_SEED §15；质量线 = 需求 §61。每条判据必须**可执行、可在浏览器中验证**。

| # | 维度 | 判据（通过标准） | 验证方式 |
|---|---|---|---|
| S1 | 首眼印象 | 从加载完成到可操作 ≤30 秒；开场（哑带边缘）截图评审不含"引擎默认场景感"：有构图、有 telegraph 前景、有区域色板 | 浏览器实机 + 截图评审（需求 §88 Scene 1） |
| S2 | 闭环完整 | 一名首次玩家能在无人指导下于 30–60 分钟内走完 12 拍闭环（醒来→休垒→雾语林→暗门→奥斯塔拉→营地→钟坠院→深窖(可选)→恩希尔→抉择→回休垒） | 3 名新玩家实机试玩，计时统计 |
| S3 | 战斗手感 | "Is it fun?"评审通过：连续 10 次弹反成功率随尝试次数上升（可学习）；轻/重/处决三档反馈有可辨差异；无一招"无感命中" | 试玩录屏 + 调试面板（帧数据/HUD 计数） |
| S4 | Boss 质量 | 奥斯塔拉、恩希尔各自：≥2 阶段、全招在节拍网格上可读、有明确 punish 窗口、胜利序列完整；恩希尔二阶段「夺拍」改变玩家资源节奏 | 浏览器实机 + 战斗 debug overlay |
| S5 | AI 合理 | 敌人具备 Idle/Patrol/Alert/Chase/Call Ally/Retreat 等行为（需求 §20）；5 种基础敌人行为可区分；幽灵八只在节拍空隙移动成立 | 实机观察 + Enemy Debugger 状态显示 |
| S6 | RPG 成立 | 升级→调音桩加点→下一次战斗可感知伤害/生存变化；至少 2 套差异明显的 Build 可行（力/技或律） | 自动化流程测试（需求 §59）+ 试玩 |
| S7 | 世界密度 | 息声领每区块六要素齐备（Landmark/Secret/遭遇/环境故事/奖励/捷径）；主路径非直线 | 关卡 checklist 走查 + 地图俯视截图 |
| S8 | 叙事闭环 | ≥5 NPC 任务线状态联动；终局双选择在 Hub 状态可见（极光/NPC 台词/Hub 音乐至少两项变化） | 实机二周目对照 |
| S9 | 视听品质 | 六区域色板互不混淆；极光带随剧情黯淡可截图对比；Boss 音乐与身份绑定；休止状态低通滤波生效 | 截图评审 + 音频走查 |
| S10 | 性能稳定 | 中端笔记本（集成显卡级）1080p/中画质 60 FPS ≥95% 帧；连续试玩 30 分钟无内存增长失控；切区无明显卡顿感 | Chrome DevTools 性能面板 + 帧时间记录 |
| S11 | UX/存档 | HUD 三资源可读且minimal；地图逐步揭示；崩溃/刷新后自动存档不丢超过 1 个检查点进度 | 实机断点测试 |
| S12 | 诚实状态 | 全部系统按 Implemented/Partial/Placeholder/Blocked 登记，无虚报 | 文档审计对照 KNOWN_ISSUES.md |

## 6. 不是什么（Explicit Non-Goals）

| 禁止成为 | 依据 | 我们的立场 |
|---|---|---|
| 静态场景 / 角色 Demo / Boss Demo / 引擎技术演示 | 需求 §1 | 必须是"玩家愿意持续玩下去"的完整循环 |
| 已有商业游戏的角色、地图、剧情、怪物、名称、资产、音乐的任何具体内容 | 需求 §5/§85；IP_SEED §16 | 全部原创；词表封闭于 IP_SEED §14 |
| "很大但什么都没有"的开放世界 | 需求 §7 | 只做息声领，密度换面积 |
| HP×10 的血量海绵 Boss | 需求 §23 | 难度=模式识别+时机+站位+资源管理 |
| 无限攻击 / 数字膨胀 RPG | 需求 §15/§25 | Stamina 经济 + 每次升级有玩法级反馈 |
| 满屏爆炸式 feedback | 需求 §16 | 三档克制的反馈强度 |
| 依赖大量过场讲故事 | 需求 §29/§31 | 环境叙事优先，过场只做节点 |
| 伪装的"UE5 级"画面（用离线渲染图充当实时画面） | 需求 §3/§51 | 程序化+原创占位资产，接口为未来高资产预留 |
| 代码量、地图面积、功能数量的竞赛 | 需求 §90 | 唯一竞赛项：QUALITY OF EXPERIENCE |
| 盗版/提取的商业游戏资产；未确认许可的 AI 资产 | 需求 §51/§85 | 程序生成 + 原创低模 + 自制材质 |

## 7. 体验原则速查（评审用 Checklist）

每次里程碑评审逐条问：

1. 玩家按下攻击键的**瞬间**，是否感到重量与反馈？（需求 §47）
2. 不看 UI 数字，能否从视听语言判断"安全/危险/可弹反"？（P1/P4）
3. 这个设计是在奖励"让世界安静下来"，还是通用数值堆砌？（P2）
4. 删掉这个空间/系统，玩家会少一次好奇吗？（P3）
5. 这段剧情拿掉过场，世界本身讲得清吗？（P5）
6. 新玩家 30 秒内能理解当前目标吗？操作有反馈吗？（需求 §81）
7. 单帧截图是否有明确的视觉焦点？（需求 §82）
8. 系统状态标注是否诚实？性能是否实测而非猜测？（需求 §78/§49）
