## 1. 技术基线映射：UE5 能力 → Vite + TypeScript + Three.js 替代方案

> 需求 §3 事实记录：本机无 UE5 引擎、无 C++ 工具链、磁盘不足 → **UE5 当前不可用（Blocked）**。
> 处理：不伪装、找替代、记录限制（本节+架构文档）、保留升级路径（数据驱动 + 模块边界 + glTF 资产接口，见 §8.3）。

| UE5 能力 | 状态 | Three.js/Web 替代方案 | 保留的升级路径 |
|---|---|---|---|
| Nanite 虚拟化几何 | Blocked→替代 | THREE.LOD 分级 + InstancedMesh 合并 + 视锥/遮挡剔除 + Draco/KTX2 压缩资产 | 资产按 glTF+LOD 组产出，可直接导入 UE5 |
| Lumen GI/反射 | Blocked→替代 | 烘焙 lightmap（区域静态光）+ 实时点光/聚光 + 屏幕空间反射(SSR)近似 + SSAO/HDR 色调映射后处理链 | 光照以"每区域 mood 参数表"驱动，可平移到 Lumen 场景配置 |
| Virtual Shadow Maps | Partial | Cascaded Shadow Maps（2–4 级联）+ PCF 软阴影 + 距离淡出 | 阴影分辨率进画质四档 |
| TSR 超分 | Placeholder | 半分辨率渲染 + TAA/FXAA 后处理（低画质档） | 画质档接口预留 |
| Niagara VFX | Partial→替代 | GPU 粒子：自定义 ShaderMaterial 点/面片系统 + 拖尾(ribbon) + 贴花(decal) | 发射器参数数据驱动（JSON），语义命名对齐 |
| World Partition / Level Streaming | Partial→替代 | 自研 chunk 流送：区域按 `RegionChunk(x,z)` 分块，距离+逻辑触发加载/卸载 glTF 场景片，Data Layer=Group 可见性层 | 分块清单即未来 World Partition 划分依据 |
| Control Rig / Anim BP / Montage | Partial→替代 | AnimationMixer + 自研 `AnimStateMachine`（locomotion blend）+ `Montage`封装（clip+notify 回调：出招帧/命中帧/收招帧） | 动画事件表数据驱动 |
| IK / Motion Warping | Placeholder→Partial | 简易 two-bone IK（脚贴地/手握武器）；攻击位移用 root motion + 落点吸附 | 接口已抽象 |
| Behavior Tree / Blackboard / EQS | Placeholder→替代 | 自研轻量 TS 行为树 + 黑板（敌我共用），感知=距离/视线/声音事件队列（呼应 P2 声音语义） | BT 序列化为 JSON，可映射 UE5 BT 资产结构 |
| UMG / Common UI | Partial→替代 | DOM/CSS Overlay（React-free，原生 TS 组件）+ 事件总线同步游戏状态；声纹 UI 用 Canvas2D/SVG | UI 与状态解耦，语义层可平移 |
| MetaSounds / UE Audio | Partial→替代 | WebAudio API：程序化合成（钟/鼓/管风琴音色全合成=原创且合法）+ 参数化音效图 + 低通滤波实现"休止"听感 | 音频事件表数据驱动 |
| GAS（能力系统） | Partial→替代 | 自研 AbilitySystem-lite：Ability/Effect/Tag（字符串 gameplay tag 层级）数据驱动 | Tag 词汇表与 UE GAS 命名同构 |
| C++/Blueprint | Blocked | TypeScript strict 模式；数值全部配置表（`src/data/*.ts`），禁止硬编码（需求 §55） | — |
| Git / 自动构建 / 自动测试 | Implemented 目标 | Git + GitHub Actions（或本地脚本）：`build + vitest + playwright` 每次提交 | — |
| 60 FPS 目标 | 中端 PC 浏览器 60 FPS（P9 实测），低档回退 30 FPS | 画质预设 Low/Medium/High/Ultra | — |

## 2. 优先级定义（P0–P4，需求 §76）

| 级别 | 定义 | 本项目示例 | 响应要求 |
|---|---|---|---|
| P0 Game-breaking | 阻止页面加载/运行、崩溃、存档损坏、闭环断裂 | 白屏；切区内存泄漏；Boss 死后无法回休垒 | 立即中断当前任务修复 |
| P1 Core gameplay | 破坏战斗/移动/锁定/AI/成长等核心循环 | 弹反判定失效；体力无限刷；敌人只会走脸 | 当前时间盒内修复 |
| P2 Player experience | 手感、反馈、引导、UI 摩擦、叙事断点 | 命中无顿帧；地图不揭示；NPC 状态不联动 | 排入本 Phase 出口前 |
| P3 Visual polish | 光照/材质/粒子/动画细节打磨 | 区域色板串味；拖尾不够"凝固声波" | 下个 Polish Phase |
| P4 Nice-to-have | 增强项，不影响判据 | 天气第四档 Storm 表现、额外 decals | 有余量才做，默认进 backlog |

调度规则：任何时点先清 P0，再保 P1，P2 按里程碑裁剪，P3/P4 只进专门打磨阶段（Phase 7/8）。

## 3. 系统状态词表（需求 §78）

| 状态 | 定义 | 判定标准 |
|---|---|---|
| Implemented | 完整实现并通过本 Phase 验收判据 | 浏览器实机验证过 + 自动化测试覆盖 + 无 P0/P1 遗留 |
| Partial | 主路径可用，但有明确缺口（行为/边缘情况/未打磨） | 缺口逐条写入 KNOWN_ISSUES.md 并可复述 |
| Placeholder | 仅占位（灰盒几何/合成音/临时动画），接口正确，为替换预留 | 资产命名带临时标记，禁止对外称完成 |
| Blocked | 受外部条件阻挡（如 UE5 不可用），已启用替代方案 | 记录：阻挡原因+替代方案+升级路径（§1 格式） |

登记方式：`docs/KNOWN_ISSUES.md` 维护「系统 × 状态 × 缺口 × 优先级」总表；每 Phase 出口评审强制更新。
