## 0. 资产策略声明（需求 §51 —— 如实，不假装 AAA 资产）

本项目**没有任何外部采购美术资产**。全部视觉内容为：

| 类别 | 当前状态 | 说明 |
|---|---|---|
| 几何 | **Placeholder（程序生成）** | Three.js BufferGeometry 参数化生成器产出低模/中模 |
| 材质 | **Implemented（原创着色器）** | GLSL 手写：干涉条纹、波纹、结晶折射，全部为本项目原创代码 |
| 纹理 | **Implemented（程序化）** | Canvas2D / WebGL FBO 运行时生成，无外部贴图文件 |
| 角色动画 | **Placeholder** | 程序化骨骼摆动 + 简单关键帧，非动捕 |
| 远景/天空 | **Implemented** | 凝声极光带为全屏 shader（见 §5） |

**结论**：我们拥有的是「AAA 视觉目标 + 正确的资产管线接口」，不是 AAA 资产本体。文档中所有"高品质"均指**设计规则与接口的完备度**，实际观感上限由程序生成质量决定。任何评审不得以"看起来像 3A 贴图"为通过标准，而以 §9 评审清单的规则符合度为标准。

## 1. 统一视觉母题：凝固的声波（Frozen Soundwave）

全项目唯一母题。**任何资产（材质/建筑/生物/道具/UI）必须至少命中以下三条语言中的一条**，否则不得入库：

1. **波纹（Ripple）**：从某个"声源点"发散的同心起伏；
2. **干涉（Interference）**：两个以上声源叠加形成的条纹（明暗相间）；
3. **结晶声纹（Solidified Waveform）**：振动被"冻结"为固体形态（音色石及其派生建筑/器官）。

### 1.1 材质波纹语言规则

- 每块波纹材质必须定义**声源锚点** `uSource`（vec3，世界空间）与**衰减半径** `uRadius`。波纹永远从锚点发散，禁止无来源的全局正弦扭曲（那是"AI 噪声汤"的典型特征）。
- 波纹幅度与距离关系：`amp = A0 * (1 - clamp(d/uRadius,0,1))^2`（二次衰减），`A0 ≤ 0.03 * UV尺度`——表面起伏不得超过物体本身尺寸的 3%。
- 波纹频率带（`uFreq`）分三档，对应材质"年龄/褪色度"：
  - FRESH（新凝结，如休垒器物）：低频宽纹，`uFreq ∈ [8, 16]`
  - TUNED（驯化/加工面）：中频，`uFreq ∈ [24, 40]`
  - FADED（褪色/哑带边缘）：高频细碎、对比降低 40%，`uFreq ∈ [48, 80]`
- 石/金属/骨质用几何波纹（normal map 级视差）；织物/肉只用 20% 强度的 albedo 波纹——**禁止全材质类别满幅波纹**。

### 1.2 干涉条纹 Shader 规则（`MAT_INTERFERENCE_*`）

双源干涉基本式（写入片段着色器统一模板）：

```glsl
float wave(vec3 p, vec3 src, float freq) {
  return 0.5 + 0.5 * cos(length(p - src) * freq + uTime * uSpeed);
}
float fringe = wave(vPos, uSrcA, uFreqA) * wave(vPos, uSrcB, uFreqB);
fringe = smoothstep(uThLo, uThHi, fringe);   // uThLo=0.42, uThHi=0.58 默认
```

- **条纹最小宽度**：屏幕上 ≥ 2px（运行时按相机距离缩放 `uFreq`），防止摩尔纹（moiré）闪烁——这是程序纹理最常见的视觉败笔。
- 干涉带只允许出现在：音色矿脉、弹反冲击残留、沉唱堂墙面、Boss 场地机关。全场景同屏干涉源 ≤ 2 组。
- 干涉条纹的颜色一律取自所在区域色板的 `accent + emissive` 两色，不得引入色板外颜色。

### 1.3 结晶声纹形态学（Timbite Morphology）

音色石/结晶是全世界共享的"通用形态词汇"，生成器 `GEO_TIMBITE_*` 必须遵守：

| 规则 | 参数 |
|---|---|
| 晶形 | 六棱柱为主，尖端偏转 ±12° 内随机（禁止完美对称生长） |
| 生长方向 | 总是背离最近的"声源锚点"（矿脉背离裂隙、胸针背离嵌座） |
| 内部纹 | 半透明琥珀内嵌同心波纹层（2–5 层，层间距 = 晶长/12 的整数倍） |
| 簇组 | 大中小三晶成簇（比例约 1 : 0.6 : 0.35），簇基部有碎裂母岩 |
| 色 | 区域 emissive 色，饱和度 55–70%，亮度 ≤ 0.8（防止满屏发光） |
| 尺寸基准 | 手持单体 4–7cm；矿脉簇 30–80cm；建筑级 ≥ 4m（仅地标使用） |

## 4. 敌人/角色剪影法则

### 4.1 振源核发光规则（敌人第一识别符）

- 每个喧堕者身上有且仅有 **1 个振源核高光面**（Discord Core），位置即弱点类型：
  - 胸腔（驼鼓/嘈壳精英）= 正面破核需弹反；背部（漂调者）= 背刺流；头顶/体外（针喉）= 远程射核。
- 核光颜色按威胁等级（全局统一，跨区不变）：
  - 杂兵 `#A8322E` 暗红 · 精英 `#8E44C8` 失谐紫 · Mini Boss 奥斯塔拉 `#D9A94E` 钟金 · 主 Boss 恩希尔 `#C9A227`+紫脉冲 · 万籁：核在体外远处音刺上，**体内无光**（剪影反转彩蛋）。
- 亮度：常态脉冲 0.6→1.0 间以**该区战斗 BPM 半速**呼吸；进入攻击前摇时亮度锁 1.0 + 半径放大 20%（telegraph 的核光层）。
- 核光在死亡时熄灭 → 掉落振源核模型（同 §1.3 结晶形态，红色系）。

### 4.2 乐器器官化轮廓

敌人剪影 = "人/兽轮廓 + 一件乐器的形态"，禁止无乐器原型的敌人：

| 敌人 | 乐器器官 | 剪影特征（10m 外可辨） |
|---|---|---|
| 嘈壳 | 木鱼/拍板 | 背壳双片开合，走动时"哒哒"张合 |
| 漂调者 | 破锣 | 喉咙处外翻金属圆片佝偻轮廓 |
| 驼鼓 | 战鼓 | 背部横置大鼓，四肢如鼓槌 |
| 针喉 | 竖琴 | 十指为散开的弦，站姿如琴架 |
| 幽灵八 | 节拍器 | 极瘦长摆锤形身体，静止时前倾 15° |
| 叠唱 | 管风琴音栓排 | 背部一排并列小管，吟唱时管口张合 |
| 奥斯塔拉 | 巨钟 | 半身与钟腔熔铸，剪影=骑士+钟形轮廓 |
| 恩希尔 | 管风琴（建筑级） | 人形与琴体共生，音管从肩背长出 |

### 4.3 主角（休止）剪影三要素

哑灰短袍（无花纹——他是"没有声音的人"，全游戏唯一不加载波纹材质的角色轮廓）、左耳剪断银铃（近景特写层）、音叉巨剑（剑格为音叉双枝形，唯一持武剪影锚点）。胸口音色石嵌座：常态熄灭，随剧情/能力逐格点亮（进度可视化）。

## 5. 天空系统：凝声极光带（The Held Chord）

无太阳世界。主光源 = 横贯天穹的极光状凝固声带。实现为全屏 shader 层 + 半球环境光。

### 5.1 结构

- 三条主带：`BAND-A`（最亮，暖金 `#FFB86B` 偏青边）、`BAND-B`（中性紫灰）、`BAND-C`（残暗红）。区域色板的 SKY 列决定各区看到的带占比。
- 带的形态 = 巨大波纹：正弦脊线 + 沿脊线的干涉细纹（复用 §1.2 模板，频率为地表的 1/8）。
- 主方向光方向始终指向 BAND-A 脊线法线，阴影柔和（shadow softness 高）——保证"无太阳但有方向"。

### 5.2 世界观时钟 → 亮度曲线（数据驱动，存 `curves/skyLuma.json`）

极光亮度 = 世界残存之歌的量 = 主线进度倒计时。关键帧（t = 归一化主线进度）：

| t | 剧情节点 | 主带亮度 | 饱和 | 附加效果 |
|---|---|---|---|---|
| 0.00 | 开场（哑带边缘醒来） | 0.85 | 1.00 | 无 |
| 0.15 | 进入休垒 | 0.82 | 1.00 | — |
| 0.40 | 击败奥斯塔拉 | 0.68 | 0.85 | BAND-C 开始出现暗斑 |
| 0.60 | 深入钟坠院/营地抉择 | 0.55 | 0.70 | 带边缘"剥落"粒子（灰，无光） |
| 0.75 | 击败万籁（可选） | 0.45 | 0.55 | 全区环境光降一档，冷偏移 +300K→-300K 视区 |
| 0.90 | 进入未竟厅 | 0.32 | 0.40 | 天空几乎只剩 BAND-A 一条细线 |
| 1.00 | 恩希尔 defeated → 结局 | **重启**：0.32 →（60s 内）0.75，救姐线恢复色暖，取半句线保持冷色 | 结局双差分 |

- 曲线插值：smoothstep；任何时刻亮度不得比"上一剧情节点存档值"更低（玩家重载旧档时天空不回退，用存档记录 `skyFloor`）。
- 昼夜：本作**无昼夜循环**（世界时间凝滞），天气与雾密度是唯一变化源——这是刻意的世界观决策，禁止后续加昼夜。

## 6. 程序化资产管线

### 6.1 生成器命名规范（强制，前缀即类别）

```
GEO_<主题>_<变体>      几何生成器        例 GEO_TIMBITE_CLUSTER_A
MAT_<母题>_<用途>      着色器材质        例 MAT_INTERFERENCE_MINEWALL
TEX_<内容>_<分辨率>    程序纹理          例 TEX_RIPPLE_STONE_512
PRP_<道具组>_<编号>    道具实例集        例 PRP_BELL_FRAG_03
CHR_<角色/敌人>_LODn   角色资产          例 CHR_TYMPANUS_LOD1
VFX_<技能或事件>       特效预制          例 VFX_PARRY_RING
ENV_<区域>_<区块>      环境装配          例 ENV_FELLCARILLON_CLIFF_E
```

- 变体后缀 `_A/B/C` ≥ 3 套防重复（需求 §52：程序生成不得看起来重复）；同一区块 90° 视野内同变体不得 ≥ 3 次。
- 所有 GEO_ 生成器输出必须带 `seed` 参数且可复现（存档=存 seed）。

### 6.2 材质槽接口（Material Slot Interface —— 替换资产的核心契约）

每个网格资产导出时声明命名槽位，着色器按槽位挂载：

| 槽位 | 含义 | 默认材质 | 替换高质量资产时 |
|---|---|---|---|
| `slot_shell` | 主体不透明表面 | MAT_RIPPLE_<区域> | 换 PBR 贴图材质，UV 保持 |
| `slot_core` | 振源核/能量体 | MAT_CORE_GLOW_<威胁色> | 保留发光，换模型形状 |
| `slot_membrane` | 振动薄膜面（鼓面/钟壁内/袍摆） | MAT_INTERFERENCE_* | 可换顶点动画布料 |
| `slot_trim` | 金属/骨饰边缘 | MAT_BONE_METAL | 直接替换贴图 |
| `slot_emissive_line` | 声纹发光刻线 | MAT_WAVE_LINE | 替换为烘焙自发光 |

### 6.3 高质量资产替换分层（未来路径，需求 §51）

### 8.1.1 复核（2026-10-07）：休垒与营地那两条裁决**不是"扩一格谓词"就能接的**

读完 `src/world/WeatherSwitch.ts`（59 行）之后，上面那张表里"算"的两条要**修正成本估计**——
它们的形状与低语林/沉唱堂/钟坠院那三区**不同**：

今天的推导是一句话：`rung = 这一区里 kind==='bell' 且立的旗被任务线追踪 的那些钟，其中有几面已经立了`，
再取 `weatherPresets[min(rung, 格数-1)]`。也就是说它认的是"**本区交互物**立的、被任务线追踪的旗"。

- **营地（`flag.brokenbar_resolved`）**：那面旗的写方是**对话**（`DLG_HALTRUNE` 的抉择），
  不是本区的任何交互物 ⇒ 想让它拨天气，要么 ① 给那一区一个**"区 → 条件"的声明**
  （`regions.json` 新形，例如 `weatherSwitch: { flag: '...' }`），要么 ② 让那面旗在本区有一个写方
  （多一个 `setsFlag` 的交互物——但那是**造一个只为天气而存在的写方**，本仓库一向拒绝这种做法）。
- **休垒（值域 `state.bells.fourth_dumb`）**：除了谓词要认 `state`，还要回答一个更根本的问题——
  **"哪个区的值域"**：值域读数**没有区属**（它不像交互物那样站在某区的地上），
  所以"本区的值域"这个概念本身要先被定义（是"这一区里有读它/写它的陈设"吗？）。

⇒ 结论：这两条的真实量级是**"设计一种新形"**，不是接线。三条候选：
**A**（推荐）`regions.json` 加一格 `weatherSwitch`，显式写"这一区的第二格由谁拨"（旗或值域）——
**代价是每个区多一行声明**，好处是推导从"猜"变成"读"；
**B** 让那两面旗各自在本区有一个写方（**不推荐**：为天气造写方 = 制造只为门禁存在的数据）；
**C** 维持现状：这两区永远走驻留格，把"它们本该有的修钟后天气"记为**已知不做**
（诚实但等于放弃两区的世界变化）。

**本批不动代码**：上面三条都超出"接线"的量级，且 8.1 那张表里"不算"的两条（深窖/未竟厅）
与"算"的三条（低语林/沉唱堂/钟坠院）**已经全部落地**（2026-10-06/07 两个提交），
所以这条线**没有半成品**——剩下的正是这张表里最贵的两格，留待明确选 A 之后再做。

### 8.1.2 裁决：选 **A**（`regions.json` 加一格 `weatherSwitch`）

上面 8.1.1 列了 A/B/C。**选 A**，理由与确切形状如下（形状先钉死，实现等 `schema.ts` 空出即可一次做完）：

**为什么不是 B/C**：B（给那两面旗各造一个本区写方）会造出**只为天气而存在的写方**——
本仓库反复拒绝这一类"为了让门禁有东西读而编的数据"；C（维持现状）等于**放弃休垒与营地的世界变化**，
而这两区恰好是"修钟之后世界该变样"最该被看见的地方（休垒是枢纽、营地是断弦线的收束地）。

**A 的确切形状**（三种形，与既有的"旗 / 值域"两套读数对齐）：

```json
// regions.json —— 与 weatherPresets 并排，声明"这一区的第二格由谁拨"
"weatherSwitch": { "flag": "flag.brokenbar_resolved" }                                  // 旗形（营地）
"weatherSwitch": { "state": { "key": "state.bells.fourth_dumb", "in": ["RUNG","MELTED","SEALED"] } }  // 值域形（休垒）
```

- **推导侧**（`src/world/WeatherSwitch.ts`）：`activeWeather` 从"数本区钟的旗"改成
  **先看 `weatherSwitch`**——这一格成立 ⇒ 奏 `[1]`（多格时按"成立的格数"依次往上）；
  没有这一格时**退回今天的行为**（数本区钟），两种来源**不叠加**（"这一区的第二格只有一个主人"）。
- **判据侧**（`scripts/weather-rules.mjs` 的 S1）：从"有第二格就必须有钟"改成
  "**有第二格就必须有 `weatherSwitch` 或挂 `PENDING_WEATHER_SWITCHES`**"；
  休垒/营地挂账的两条**同批销掉**（它们从此有主人）。
- **为什么值域那一形要带 `in`**：值域是多值的（`INTACT/RUNG/MELTED/SEALED`），
  "哪几个值算'这一格成立'"是**设计读数**（休垒：敲响/熔钟/封口三种都算"她做了决定"，
  只有 `INTACT` 不算），把它写在数据里而不是代码里——**与 `advanceOn.state` 同一形，不新造语法**。

**代价如实**：每个有第二格的区多一行声明（今天 5 个区）；好处是推导**从"猜"变成"读"**，
而且"这一区的第二格归谁"从此在数据里看得见——这正是 §8.1.1 里那句"值域没有区属"的解法：
**区属由这一格声明提供，而不是由值域自己携带**。

> 口径提醒：本节裁的是**判据形状**（谁有资格当天气条件），不是**读数**。
> 任何新接进来的切换都必须复用 §8 已有的雾密度/明度/对比三格，**不许为它编新数**。

> **已落地（2026-10-08，KI-094② 最后两格）**：`schema.ts > RegionData.weatherSwitch` 建类型；
> `regions.json` 休垒走值域形（`state.bells.fourth_dumb` 的 RUNG/MELTED/SEALED，`INTACT` 不算——还没拉殊不构成换天的理由）、
> 营地走旗形（`flag.brokenbar_resolved`，不为天气另立新旗）；推导先读这一格、没有才数钣，
> 两种来源同时在场由判据 S1 记 ERROR。两条 `PENDING_WEATHER_SWITCHES` 同批销掉，门禁 WARN 4 → 2。
