## 常做的四件套（每一批都跑）

1. **先量后写**：脏工作区的红绿不能写进"主干债务"（KI-127 的教训）⇒ 必要时在 `git worktree` 平面上量。
2. **数据 → 判据 → 机制 → 守卫**：没有消费方的数据不许入表（§55/KI-047）；门要能被合成夹具喂。
3. **写完量**：反向实测（改坏 ⇒ 门必须红）＋ 全量套件 ＋ `tsc` ＋ `validate-data` ＋ `build`。
4. **入账再提交**：一行 KI-NNN 说清"病是什么 / 为什么值得单独立行 / 做了什么 / 怎么量的 / 还欠什么"，
   提交信息按 `area+test: KI-NNN 描述 —— …` 的旧例。
