**量测配方（可复跑）**：
1. `npm run dev` 起服；浏览器开 `http://localhost:5173/?fresh=1`（无头通道，直接开跑）；
2. 页面里 `window.__caesura.loop.tickFrame(1/60)` 手动步进（**看不见的标签页里 RAF 不触发**）；
3. `gl.readPixels` **立刻**回读那一帧（帧外读画布是**陈旧缓冲**，不是实时画面）；
4. 按亮度画 ASCII 灰度图；DOM 几何用 `getBoundingClientRect` / `getComputedStyle` 量。

**两条坑（都踩过）**：① 合成事件**不会**触发浏览器的原生滚动 ⇒ 不不「滚轮滚不动」这条结论无效；
② 页面重绘落定前取读数 ⇒ 量到的是上一个状态。

## 常做的四件套（每一批都跑）

1. **先量后写**：脏工作区的红绿不能写进"主干债务"（KI-127 的教训）⇒ 必要时在 `git worktree` 平面上量。
2. **数据 → 判据 → 机制 → 守卫**：没有消费方的数据不许入表（§55/KI-047）；门要能被合成夹具喂。
3. **写完量**：反向实测（改坏 ⇒ 门必须红）＋ 全量套件 ＋ `tsc` ＋ `validate-data` ＋ `build`。
4. **入账再提交**：一行 KI-NNN 说清"病是什么 / 为什么值得单独立行 / 做了什么 / 怎么量的 / 还欠什么"，
   提交信息按 `area+test: KI-NNN 描述 —— …` 的旧例。
